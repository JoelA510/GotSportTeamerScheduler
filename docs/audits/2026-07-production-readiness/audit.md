## Appendix: Refuted During Verification

No finding in this audit's working set was fully discarded by the adversarial verification pass — every area's finding set survived with the underlying claim intact. However, several findings had their supporting evidence corrected or narrowed during verification. These corrections are recorded here so a future pass does not re-derive or re-litigate them:

- **RLS and tenancy — stale write policies on locations/coaches/teams:** the original evidence list mis-grouped the coach-delete RPC under `20260613000003_schedule_team_delete_rpcs.sql`. The coach-delete RPC actually lives in a separate migration, `supabase/migrations/20260613000000_coach_delete_rpc.sql` (`20260613000003` in fact contains `admin_delete_team`, `admin_cancel_game_assignment`, `admin_cancel_practice_assignment`). Corrected in the finding table above. Does not affect the core claim.
- **RLS and tenancy — `organizations` table JWT-claim policy:** the original citation for the SELECT-only "Organizations: members can access" policy was approximate ("~1090"). Verified exact location: `supabase/migrations/20260331000000_definitive_schema.sql:953-954`. Corrected above.
- **RPC / Zod / audit_log — `record_audit_event` authorization gap:** the `audit_log` SELECT-only RLS policy block was cited as `1191-1199`; verified exact span is `1191-1202`. Does not change the substance (SELECT-only, no INSERT/UPDATE/DELETE policy exists).
- **Data layer — migrations missing revert/smoke scripts:** the original pass found 7 migrations with no matching revert/smoke script and characterized the gap as "bounded." Verification found 3 additional migrations in the same window with the same gap (`20260421060000_coach_leads.sql`, `20260502001000_division_roster_constraints.sql`, `20260503000000_secure_coach_lead_scoping.sql`), bringing the true total to **10**, not 7. The finding table above reflects the corrected count of 10; the "bounded, specific gap" framing (i.e., not an abandoned convention — later migrations all have both scripts) still holds.
- **Testing — E2E scenarios asserting on mock-DB internals:** the "no data leakage" calendar-feed assertion was originally cited at `tests/e2e/features/Pillar2_CoachDailyLoop.feature:12-15` and alternatively attributed to `tests/e2e/features/calendar_sync.feature`. Verified exact location: `Pillar2_CoachDailyLoop.feature:17-21` (the "no data leakage" step specifically at line 21); `calendar_sync.feature` does not contain this scenario at all. Corrected above.
- **Accessibility — no automated a11y testing / no post-redesign re-certification:** `docs/ui/agent-ui-ux-guidelines.md` was originally cited at both lines 83 and 325; the file is 128 lines total, so line 325 does not exist. Corrected to cite line 83 only.
- **Security — npm audit / stale lockfile:** the original framing claimed the lockfile refresh would close "4 real production react-router CVEs." Per-CVE verification against each GHSA's own scope note found that 3 of those 4 (`RSCErrorHandler` XSS, SSR-hydration constructor injection, DoS via inefficient route matching) are explicitly restricted to Framework Mode/Data Mode/RSC applications, which this app is not (confirmed classic `<BrowserRouter>`, no SSR, no data router). Only the open-redirect CVE is independently reachable; the CSRF-bypass CVE requires a documented waiver (major-bump-only fix, RSC-mode-only exposure). Severity is retained at high — the justification is now the governance-process violation (zero documented waivers for 7 unwaived findings) and the confirmed direct-dependency/open-redirect exposure, not an inflated CVE-applicability count. The finding table above reflects the narrowed justification.

No finding was downgraded to "not a finding" or removed outright; all corrections were scope/citation refinements that left the core claim standing.

## Coverage & Limitations

A completeness-critic pass was not run for this audit (no critic report was supplied as input). Readers should treat the following as known boundaries of this pass rather than a certified-complete coverage statement:

- **Areas covered:** Docs drift, RLS and tenancy, RPC/Zod/audit_log conformance, Data layer, Error handling, Mock/real client parity, Testing, Security, Observability, Performance, Accessibility, Operability — all 12 areas requested were investigated and each produced at least one file-path-evidenced finding (a "clean" area with zero findings did not occur in this pass).
- **E2E:** the full Playwright suite was not executed as a baseline run in this session; only the targeted scenarios cited in the Testing section were executed to verify specific claims (mock-DB-assertion pattern, coverage-mode performance budget). A full `npx bddgen && npx playwright test` baseline run (CI's `--workers=1` mode) was not performed and could surface additional gaps not captured here.
- **npm audit triage:** severity/reachability was assessed per-package and, for react-router specifically, per-CVE against each advisory's own scope text. It was not re-verified against a live exploit attempt; the "genuinely reachable" / "Framework-Mode-only" classifications rest on static confirmation that this app uses classic `<BrowserRouter>` with no SSR/RSC/data-router usage anywhere in `frontend/src`.
- **RLS coverage:** the two findings in the RLS and tenancy section were found by diffing policy-creation and policy-drop statements across all matching migrations for `locations`, `coaches`, `teams`, and `organizations`. The remaining ~20+ org-scoped tables in the schema were not individually re-audited table-by-table in this pass beyond what `check:advisors` already covers; a full manual policy audit of every table was out of scope for the time available.
- **Verification labels:** every finding above is labeled "executed" (a command was run and its output observed) or "statically reviewed" (the file was read and reasoned about, but no command was run to confirm the runtime behavior). No finding in this report carries a "fully validated" label, since no finding's proposed fix was implemented and re-tested in this pass — this is a gap-analysis audit, not a remediation pass.
